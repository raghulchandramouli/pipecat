# Sarvam streaming speech

The demo uses Sarvam `bulbul:v3`, speaker `shubh`, English (`en-IN`) or Hindi-English (`hi-IN`), and 24-kHz
mono PCM16. `InterviewSession.create_tts()` creates the session's single speech
service. Set `SARVAM_API_KEY` in the process environment, pass `api_key=` to the
factory, or supply `config.providers.tts.credentials`. The smoke command also
loads `demo/.env`. Credentials remain server-side.

Place `session.create_reply_guard()` before `session.create_tts()` and the output
transport after TTS. A complete approved Start/Text/End reply is required before
speech starts; PCM streams as it arrives. The transport is Sarvam's
[HTTP streaming API](https://docs.sarvam.ai/api/api-guides-tutorials/text-to-speech/streaming-api/http-stream),
with an explicitly requested `linear16` codec. No model download or local inference
server is required.

The adapter reuses the existing guarded scheduler for bounded admission and reply
ownership; its synthesis transport makes no Rumik calls. Interruption cancels the
owned HTTP stream, drops queued stale replies, and checks the playback generation
before each audio chunk. Candidate advancement preserves ownership; speech,
replacement controls, and reconnection invalidate it. Normal End drains accepted
speech; Cancel/Stop discard it. A failed stream reports a nonfatal error and does
not block subsequent valid replies. Partial failed speech does not commit a full
spoken-text frame.

`on_sarvam_metrics` reports queue wait, first PCM output, complete request time,
and generated audio duration. These measure server-side processing, not audio
heard in a browser; no word timestamps or audible-stop measurement is claimed.

From the repository root:

```bash
uv pip install --python demo/.venv/bin/python -r demo/requirements-tts.txt
demo/.venv/bin/python -m demo.scripts.smoke_sarvam_tts --text 'Thank you. What did you change first?'
```

The [live measurement](../sarvam/results/adapter-smoke.json) and
[generated WAV](../sarvam/results/adapter-smoke.wav) record real provider evidence.
The smoke checks streamed lifecycle/context ownership and saves the source hash.
Sarvam replaces the demo's active TTS selection. The explicit `create_rumik_tts()`
factory and Rumik artifacts remain available for reproducing earlier experiments;
the downloaded weights remain under root `models/`.

## Hinglish

For Hindi-English speech, set `config.providers.tts.language_code="hi-IN"`.
Send naturally mixed text, with Hindi in Devanagari and English technical terms
in Latin script. For realtime STT, use `saaras:v3-realtime`,
`language_code="auto"` (or `hi-IN`), and `mode="codemix"` in the Sarvam service
settings. `codemix` applies to final transcripts; partials remain plain
transcription. These fields are represented in `config.providers.sarvam` for the
browser composition. Instruct Gemini to reply naturally in Hinglish while retaining
the strict completion marker and coaching JSON contract; only approved `speak`
text goes to TTS. The current deterministic controller prompts remain English.

Official references: [realtime STT](https://docs.sarvam.ai/api/api-guides-tutorials/speech-to-text/realtime-streaming)
and [code-mixed input/output](https://docs.sarvam.ai/api/getting-started/building-for-india).

The [Hinglish WAV](../sarvam/results/hinglish/adapter-smoke.wav) was generated by
Bulbul with first PCM output in 0.408 seconds and 3.925 seconds of audio generated
in 1.028 seconds. [REST STT round-trip evidence](../sarvam/results/hinglish/stt-roundtrip.json)
retains Hindi plus the English words `project`, `technical problem`, and `solve`.
This is a synthetic audio test, not microphone, realtime STT, or full interview acceptance.

```bash
demo/.venv/bin/python -m demo.scripts.smoke_sarvam_tts --language hi-IN \
  --text 'ठीक है, अब बताइए आपने इस project में कौन सा technical problem solve किया?' \
  --output-dir demo/sarvam/results/hinglish
demo/.venv/bin/python -m demo.scripts.check_hinglish_stt
```
